ServiceVoice golden dataset · v1 draft

Open the versioned JSON dataset. This corpus contains 32 newly authored synthetic cases: 10 regression, 15 development and 7 holdout. There are 25 text-model cases, six manual voice/evidence scenarios and one browser outcome scenario.

Review status: draft, awaiting human review. These are explicit acceptance expectations, not a declaration that the agent passes. The author had access to application code and historical test reports. Holdout cases are withheld from default development runs, but this is not an independent benchmark and the holdout is not secret.

What a case means

FieldContract
id / familyStable identifiers for a specific case and its behavioral family. A wording or expected-behavior change requires a new dataset version. A materially different case gets a new ID. Related variants stay in the same split.
splitregression covers observed incident patterns; dev supports iteration and grader calibration; holdout requires explicit selection and should be reviewed after a candidate is frozen.

The runner separately reports pending proposals. Complete-intake preparation cases require actual proposal creation, so a model that merely does nothing cannot pass the preparation check. These checks do not independently prove that the spoken readback was correct or understood.
expected.finalSupported final-state assertions. These include appointment counts/status, historical proposal counts, current service and vehicle, and the saved advisor handoff_status where required. Missing fields are deliberately not mechanically asserted. Each richer fact in the rubric needs explicit evidence and review rather than an inferred pass.

tool_argument_checks (optional)A recursive subset of arguments on a successful named tool call after a particular turn. The exact-time regression requires the requested date and 14:00 filter; the held-out range challenge requires both exclusive boundaries after a changed availability constraint. This checks essential business constraints without demanding irrelevant argument formatting or an entire fixed tool trajectory.

Grading without false green results

Keep mechanical results, semantic review, UI results and audio review separate. Report failed for an observed hard-invariant failure, needs_review for unreviewed semantics and not_run for a layer that was not executed. Never turn a missing recording, unsupported fixture, skipped case, request-budget exhaustion or absent reviewer into a pass. Do not average a premature booking, false action claim or cross-session access into a high overall score.

The semantic reviewer sees the synthetic inputs, resolved fixture facts, actual tool outcomes, relevant state and the saved response. They should mark each criterion pass, fail or insufficient evidence, with a short evidence reference. A model judge can help triage, but its labels require calibration against human judgments before being used as a release gate. A model should not be the sole judge of its own action correctness.

The local review sidecar binds the frozen report digest, run ID, dataset digest, case ID, attempt and output digest. Each criterion and the five dimensions—factual grounding, action truthfulness, task completion, consent and corrections, and conversation quality—starts pending. Graded values are pass, fail or uncertain with evidence. Assistant and judge reviews remain advisory in this version; only an identified human review can satisfy the semantic gate, and identity is self-declared local metadata. The sidecar never rewrites the original experiment report or overrides a mechanical failure.

Latency measurements must identify their measurement boundary and sample count. Browser speech events, transcript gaps, model timing and acoustic input-to-output latency are different measurements. Faster responses do not excuse omitted readbacks, conditional consent, incorrect time filters or unsupported completion claims.

Benchmark the agentic harness through complementary evidence: deterministic fault and load tests for admission, concurrency, idempotency and recovery; actual model/tool runs for decisions and accuracy; reviewed responses for hallucination, task completion and naturalness; and controlled audio traces for voice behavior. Direct-model runs do not measure the JEV routing path. Report component errors, tool durations and model request counts alongside end-to-end timings. This small corpus does not establish exhaustive coverage or a population-level success rate.

Privacy and language coverage

All caller lines are newly authored. The fictional identity is Taylor Reed with a reserved fictional-range US callback number and a synthetic vehicle. Regression cases preserve failure patterns without copying private customer wording, names, phone numbers, provider call IDs, recordings or session capabilities. No dataset export should include credentials, raw private traces or the runtime database.

Multilingual cases sample language switching, negation and information-only intent. These examples are not a supported-language list and are not inserted into the production prompt as a whitelist. Fluent human reviewers must check meaning. ASR, generated text, synthesized audio and captions require separate evidence; a correct stored phone number cannot certify its audible readback.

Versioning and holdout discipline

  1. Freeze the candidate code, prompt, tool schema, model identity, dataset hash and evaluator version in each run manifest.
  2. Run regression and development cases, retaining failures and request-budget stops. Do not silently retry only failed cases and report the best attempt.
  3. Review semantic outcomes and inspect disagreements between mechanical and semantic results.
  4. Run the holdout explicitly after freezing a candidate. Treat results as challenge coverage rather than a statistically precise production success rate.
  5. If a holdout finding changes prompts or code, move its entire family into regression in the next dataset version. Author a new challenge family and record why it is distinct.
  6. Preserve the old dataset and reports. Keep corrections and reviewer decisions attributable rather than overwriting failure history.

The existing unit, concurrency, recovery and browser suites remain separate evidence. Linking a golden case to a passing unit test does not execute its conversation. These 32 cases are a starter acceptance corpus; expansion should follow real failures and business coverage, not a target case count.
